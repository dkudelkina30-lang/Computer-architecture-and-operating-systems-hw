# HW-1 — моделирование сборочной линии

Консольная программа на C, которая моделирует работу участка завода. Детали проходят обработку на станках, контроль качества и перевозку роботами, а затем собираются в изделия. Программа показывает каждое событие на линии и в конце печатает итоговую статистику.

Документы в папке:
- `REPORT.md` - отчёт по заданию;
- `EXPLANATION.md` - отчёт;
- `LINE_BY_LINE.md` - пояснение к каждой строке кода.

## Варианты запуска

| Что нужно | Команда |
|---|---|
| Просто посмотреть, как работает программа | `./bin/assembly_line` |
| Показать работу наглядно, с паузами между событиями | `./tests/demo.sh` |
| Запустить конкретный сценарий из файла | `./bin/assembly_line -c configs/01_basic.cfg` |
| Замедлить вывод, чтобы следить за событиями | `./bin/assembly_line -c configs/01_basic.cfg -d 200` |
| Получить одинаковый результат при каждом запуске | `./bin/assembly_line -s 13` |
| Увидеть только итоги, без потока событий | `./bin/assembly_line -c configs/01_basic.cfg -q` |
| Сохранить журнал в другой файл | `./bin/assembly_line -l мой_журнал.log` |
| Запустить без журнала | `./bin/assembly_line -l -` |
| Ограничить модельное время | `./bin/assembly_line -t 50` |
| Проверить, что всё работает правильно | `make test` |
| Вспомнить ключи | `./bin/assembly_line -h` |

Ключи можно сочетать, например:

```bash
./bin/assembly_line -c configs/10_multi_product.cfg -s 7 -d 100
```

### Все ключи

| Ключ | Что делает | По умолчанию |
|---|---|---|
| `-c файл` | взять параметры из файла | встроенный сценарий «редукторы» |
| `-s число` | начальное значение генератора случайных чисел (seed) | из файла или по текущему времени |
| `-d мс` | пауза после каждого события, в миллисекундах | 0 (без пауз) |
| `-l файл` | куда писать журнал; `-` — не писать | `assembly_line.log` |
| `-q` | тихий режим: на консоль только итоги | выключен |
| `-t число` | ограничение модельного времени | 1 000 000 |
| `-h` | справка | |

## Вывод программы

### 1. В начале - параметры модели

```
Параметры: роботов 2 (перевозка 2), контролёров 1 (контроль 1), постов 1 (сборка 5)
Накопители: очередь станка 3, выход станка 1, вход ОТК 3, выход ОТК 2, комплект 4
Деталь SHAFT: заготовок 6, брак 10%, переделка с операции 2 до 1 раз, маршрут: LATHE(4) GRIND(3)
Деталь HOUSING: заготовок 5, брак 8%, брак списывается, маршрут: MILL(6) DRILL(3)
Изделие REDUCER: план 4, комплект: SHAFT x1 GEAR x2 HOUSING x1
```

### 2. Во время работы - события, по одному в строке

```
[t=   27] БРАК       ОТК-1     в HOUSING#6 обнаружен брак
   │          │          │       └ что произошло
   │          │          └ кто: станок, контролёр, робот, пост, склад
   │          └ вид события
   └ модельное время
```

Обозначения: `SHAFT#1` — деталь «вал» номер 1; `LATHE-1` — первый токарный станок; `ОТК-1` — первый контролёр; `РОБОТ-2`, `ПОСТ-1` — робот и сборочный пост.

| Вид события | Когда появляется | Пример |
|---|---|---|
| `СОЗДАНИЕ` | склад выпустил новую заготовку | `создана деталь SHAFT#1, осталось заготовок 5` |
| `ОЧЕРЕДЬ` | деталь встала в очередь или в накопитель | `SHAFT#1 поставлена: очередь LATHE (1/3)` |
| `ПЕРЕВОЗКА` | робот взял или доставил деталь | `взял SHAFT#1: склад заготовок -> очередь LATHE` |
| `ОП.НАЧАЛО` | станок начал операцию | `операция 1/2 над SHAFT#1, длительность 4` |
| `ОП.КОНЕЦ` | станок закончил операцию | `операция 1/2 над SHAFT#1 завершена` |
| `ПРОСТОЙ` | станок или контролёр не может отдать деталь — накопитель полон; и когда место освободилось | `выходной накопитель заполнен — станок приостановлен` |
| `КОНТРОЛЬ` | начало проверки, деталь признана годной | `GEAR#2 годна — направляется на сборку` |
| `БРАК` | при проверке найден брак | `в GEAR#5 обнаружен брак` |
| `ПЕРЕДЕЛКА` | брак отправлен на повторную обработку | `GEAR#5 возвращается на операцию 2 (DRILL), переделка 1 из 2` |
| `СПИСАНИЕ` | брак переделать нельзя, деталь выбывает | `HOUSING#6 списана: переделка не предусмотрена` |
| `КОМПЛЕКТ` | годная деталь пришла к сборочному посту | `SHAFT#1 поступила в комплект (1/4)` |
| `СБОРКА` | собран полный комплект, началась сборка | `начало сборки REDUCER №1 из комплекта: SHAFT#1, GEAR#2, ...` |
| `ВЫПУСК` | изделие готово | `выпущено изделие REDUCER №1, по плану 1/4` |
| `СИСТЕМА` | запуск линии | `запуск: станков 5, контролёров 1, роботов 2, постов 1` |
| `!ИНВАРИАНТ` | нарушено правило модели. В исправной программе не появляется; если появилось, это ошибка | |

Если поток событий идёт слишком быстро, добавьте ключ `-d`, например `-d 200`.

### 4. Журнал

Всё, что программа показывает, она записывает и в файл `assembly_line.log`. Журнал пишется даже в тихом режиме (`-q`) и даже при остановке по Ctrl+C. Посмотреть журнал:

```bash
less assembly_line.log 
```

## Чем может закончиться работа

| Что напечатано | Когда так бывает | Код завершения |
|---|---|---|
| `ПЛАН ВЫПОЛНЕН` | все изделия по плану собраны | 0 |
| `Ошибка конфигурации: файл:строка: ...` | ошибка в файле параметров; указана строка с ошибкой | 1 |
| `Некорректное значение параметра -d: 'abc'` | неверный ключ запуска | 1 |
| `ИСХОДНЫЕ ДЕТАЛИ ИСЧЕРПАНЫ` | из-за брака кончились заготовки, план выполнить нельзя | 2 |
| `Производство невозможно: ...` (сразу, без событий) | по параметрам видно, что собрать изделие нельзя: нет станка нужного типа, нет роботов, комплект больше накопителя | 3 |
| `ПРОИЗВОДСТВО НЕВОЗМОЖНО (взаимная блокировка)` | линия встала: детали застряли, и ни одна больше не может сдвинуться | 3 |
| `ПРЕВЫШЕН ЛИМИТ ВРЕМЕНИ` | модельное время дошло до значения ключа `-t` | 4 |
| `ПРЕРВАНО СИГНАЛОМ` | нажато Ctrl+C или процесс остановлен командой `kill` | 130 / 143 |

Код завершения последнего запуска можно посмотреть командой:

```bash
echo $?
```

## Готовые сценарии (`configs/`)

| Файл | Что показывает | Чем закончится |
|---|---|---|
| `01_basic.cfg` | обычная работа: брак, переделка, списание, приостановка станков | план выполнен |
| `02_no_defects.cfg` | идеальное качество, брака нет | план выполнен |
| `03_rework_heavy.cfg` | много брака и многократные переделки | план выполнен |
| `04_raw_exhausted.cfg` | брак только списывается, заготовок мало | заготовки исчерпаны |
| `05_deadlock.cfg` | линия «застревает» | взаимная блокировка |
| `06_no_machine.cfg` | для операции нет нужного станка | производство невозможно (сразу) |
| `07_kit_too_big.cfg` | комплект не помещается в накопитель | производство невозможно (сразу) |
| `08_bad_syntax.cfg` | ошибка в файле параметров | ошибка конфигурации |
| `09_bottleneck.cfg` | медленный станок тормозит быстрые | план выполнен, есть события «ПРОСТОЙ» |
| `10_multi_product.cfg` | два вида изделий, два сборочных поста | план выполнен |

Пример:

```bash
./bin/assembly_line -c configs/05_deadlock.cfg -d 100
```
