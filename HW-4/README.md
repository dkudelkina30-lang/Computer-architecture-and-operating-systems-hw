# HW-4 - сборочная линия  

| Программа      | Что делает                                                                                                                  |
| -------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `tcp_server`   | хранит состояние линии, раздаёт работу, принимает результаты и подводит итоги                                               |
| `tcp_worker`   | запускает одного участника: склад, станок, контролёра, робота или пост                                                      |
| `tcp_observer` | показывает параметры линии, общий поток событий и итоги, при позднем или повторном подключении показывает текущее состояние |
| `tcp_control`  | показывает список клиентов, отключает выбранного клиента и разрешает подключить его заново                                  |

---
## 1. Сборка

```bash
cd HW-4
make
```
  
В папке `bin/` появятся четыре программы.

```bash
make test # сценарии модели и работа TCP-клиентов
make test-network # отдельный тест с двумя сетевыми узлами Linux
make clean # удалить bin, вывод тестов и журналы
```
## 2. Как запускать
### Быстрая демонстрация
Скрипт сам запускает сервер, всех участников и одного наблюдателя.

```bash
./tests/demo.sh -c configs/01_basic.cfg
PORT=4405 ./tests/demo.sh -c configs/11_reconnect.cfg -d 100
```
### Вручную на одном компьютере
Сначала запустите сервер. В другом терминале подключите наблюдателя (если он нужен), затем узнайте список участников и запустите их.

```bash
# терминал 1: сервер
./bin/tcp_server 127.0.0.1 4404 -c configs/01_basic.cfg -d 100
# терминал 2: наблюдатель
./bin/tcp_observer 127.0.0.1 4404 0
# терминал 3: узнать, какие участники нужны
./bin/tcp_server 127.0.0.1 4404 -c configs/01_basic.cfg -L
# запустить всех участников на этом компьютере
while read -r role idx; do
./bin/tcp_worker 127.0.0.1 4404 "$role" "$idx" > "$role-$idx.log" &
done < <(./bin/tcp_server 127.0.0.1 4404 -c configs/01_basic.cfg -L)
wait
```

Отдельного участника можно запустить в своём терминале, например `./bin/tcp_worker 127.0.0.1 4404 machine 0`. Номера участников начинаются с `0`. Линия начинает работу, когда подключатся все участники. Наблюдатели для запуска линии не нужны.
### На нескольких компьютерах

На сервере укажите `0.0.0.0`, чтобы слушать на сетевых интерфейсах и на `127.0.0.1`. Ниже `192.168.1.10` приведён для примера: нужно заменить его на реальный адрес сервера.

```bash
# компьютер с сервером
./bin/tcp_server 0.0.0.0 4404 -c configs/01_basic.cfg -w 60
# другие компьютеры, по одному запуску на каждую роль и номер из списка -L
./bin/tcp_worker 192.168.1.10 4404 warehouse 0
./bin/tcp_observer 192.168.1.10 4404 0
```
### Ключи сервера

| Ключ | Что делает | По умолчанию |
|---|---|---|
| `-c файл` | взять параметры из файла | встроенный сценарий |
| `-s число` | начальное значение генератора случайных чисел | из файла или по времени |
| `-d мс` | длительность единицы модельного времени (`1..1000` мс) | `50` |
| `-l файл` | файл журнала; `-` - не писать журнал | `line.log` |
| `-q` | убрать параметры и системные события с консоли сервера, оставить запуск и итоги | выключен |
| `-t число` | лимит модельного времени | из файла или `1 000 000` |
| `-w секунды` | сколько ждать участников при старте и при разрыве связи (`1..300` с) | `15` |
| `-L` | вывести список `роль номер` без запуска сервера | выключен |
| `-h` | вывести справку | |

## 3. Наблюдатели и пульт

Можно одновременно подключить до 16 наблюдателей с разными номерами (`0..15`). Чтобы отключить одного из них, нажмите Ctrl+C в его терминале. Чтобы подключить снова, повторите команду с тем же номером: он получит новый снимок и продолжит видеть события. Пропущенные события остаются в журнале сервера.
Пульт запускается на компьютере сервера через `127.0.0.1`.

```bash
./bin/tcp_control 127.0.0.1 4404 list
./bin/tcp_control 127.0.0.1 4404 disconnect machine 0
./bin/tcp_control 127.0.0.1 4404 allow machine 0
./bin/tcp_worker 127.0.0.1 4404 machine 0
```

`disconnect` завершает выбранного клиента и запрещает подключение с тем же номером. `allow` снимает запрет, а процесс запускается заново обычной командой на нужном компьютере. Для наблюдателя укажите, например, `disconnect observer 1` и `allow observer 1`. У рабочего клиента сохраняются деталь и незаконченная работа, после подключения ему выдаётся оставшееся время. Если рабочий не вернётся до истечения `-w`, линия завершится. Отключение наблюдателя этому не мешает.

## 4. Вывод программы

Сервер печатает параметры, системные сообщения и итоги. Рабочий процесс показывает только то, что относится к его роли. Наблюдатель, запущенный до участников, видит тот же поток, что и в журнале: сначала параметры линии, затем подключения и события всех ролей.

```text
[t= 0] СИСТЕМА Склад процесс подключился (1 из 5)
...
[t= 2] ОП.НАЧАЛО LATHE-1 операция 1/1 над SHAFT#1, длительность 25
[t= 27] ОП.КОНЕЦ LATHE-1 операция 1/1 над SHAFT#1 завершена
```

  

| Событие | Когда появляется |
|---|---|
| `СИСТЕМА` | запуск линии, подключение и завершение рабочих процессов |
| `СОЗДАНИЕ`, `ОЧЕРЕДЬ` | заготовка выпущена или деталь поставлена в накопитель |
| `ОП.НАЧАЛО`, `ОП.КОНЕЦ`, `ПРОСТОЙ` | операция началась или закончилась; накопитель заполнен или место освободилось |
| `ПЕРЕВОЗКА` | робот взял или доставил деталь |
| `КОНТРОЛЬ`, `БРАК`, `ПЕРЕДЕЛКА`, `СПИСАНИЕ` | проверка и результат проверки |
| `КОМПЛЕКТ`, `СБОРКА`, `ВЫПУСК` | комплектование, начало сборки и выпуск изделия |
| `!ИНВАРИАНТ` | обнаружено нарушение правила модели |

Сетевые сообщения о подключении наблюдателей выводятся отдельно на сервере. Если наблюдатель подключается после участников или возвращается, перед новыми событиями он получает снимок текущего состояния.
## 5. Варианты завершения

| Код           | Когда                                                                                        |
| ------------- | -------------------------------------------------------------------------------------------- |
| `0`           | план выполнен, также код отдельного клиента, отключённого пультом                            |
| `1`           | ошибка ввода, конфигурации или сети, клиент не зарегистрирован или его подключение запрещено |
| `2`           | исчерпаны заготовки, план выполнен не полностью                                              |
| `3`           | производство невозможно, линия заблокировалась или истекло время ожидания участника          |
| `4`           | достигнут лимит модельного времени                                                           |
| `5`           | при выполненном плане обнаружено нарушение правил модели                                     |
| `130` / `143` | сервер остановлен по SIGINT (Ctrl+C) / SIGTERM                                               |

При штатном завершении сервер передаёт подключённым клиентам причину и код. У наблюдателя причина указана только в итогах, код можно посмотреть через `echo $?`.

## 7. Тесты
`make test` проверяет сценарии линии, независимый вывод, несколько наблюдателей, повторный вход наблюдателя и рабочего клиента, остановку во время операции и отсутствие участника. `make test-network` создаёт два отдельных сетевых пространства имён Linux, запускает сервер в одном, рабочих клиентов в другом, а наблюдателей на обоих узлах. Для второго теста нужны `iproute2`, `unshare` и `nsenter`, а в Linux должны быть разрешены пользовательские и сетевые пространства имён. Вывод каждого запуска сохраняется в `tests/out/`.
