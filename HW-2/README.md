# HW-2 - многопоточная модель сборочной линии

Программа на C моделирует участок завода: детали обрабатываются на станках, проходят контроль качества, перевозятся роботами и собираются в изделия. Каждый участник линии (склад, станок, контролёр, робот, сборочный пост) работает в отдельном потоке. Потоки общаются через общие данные, защищённые мьютексом, и ждут друг друга на семафорах.

Собираются две программы с одинаковым поведением:
- `bin/line_sem` - ожидание сделано на семафорах POSIX (`sem_t`);
- `bin/line_cond` - то же самое на мьютексе и условной переменной (`pthread_cond_t`).

---


## 1. Запуск

| Что нужно | Команда |
|---|---|
| Запуск со встроенным сценарием | `./bin/line_sem` |
| Наглядная демонстрация (медленно) | `./tests/demo.sh` |
| Конкретный сценарий из файла | `./bin/line_sem -c configs/01_basic.cfg` |
| То же на условных переменных | `./bin/line_cond -c configs/01_basic.cfg` |
| Медленнее, чтобы следить за событиями | `./bin/line_sem -c configs/01_basic.cfg -d 200` |
| Быстрее | `./bin/line_sem -c configs/01_basic.cfg -d 5` |
| Только итоги, без потока событий | `./bin/line_sem -c configs/01_basic.cfg -q` |
| Журнал в другой файл / без журнала | `-l мой.log` / `-l -` |
| Ограничить модельное время | `./bin/line_sem -t 50` |
| Справка | `./bin/line_sem -h` |

### Все ключи

| Ключ | Что делает | По умолчанию |
|---|---|---|
| `-c файл` | взять параметры из файла | встроенный сценарий «редукторы» |
| `-s число` | начальное значение генератора случайных чисел | из файла или по времени |
| `-d мс` | сколько миллисекунд длится одна единица модельного времени | 50 |
| `-l файл` | файл журнала; `-` - не писать | `line.log` |
| `-q` | тихий режим: на экран только итоги | выключен |
| `-t число` | лимит модельного времени | 1 000 000 |
| `-h` | справка | |

Важно: потоки работают по-настоящему параллельно, поэтому два запуска с одинаковыми параметрами могут немного отличаться (например, брак достанется другой детали). Это нормально для многопоточной программы.

## 2. Сигналы

Программа реагирует на сигналы во время работы. PID можно узнать командой `pgrep line_sem` (или `demo.sh` печатает его сам). Из другого терминала:

| Сигнал | Команда | Что происходит | Код выхода |
|---|---|---|---|
| SIGINT | Ctrl+C | остановка, итоги и журнал сохраняются | 130 |
| SIGTERM | `kill <pid>` | то же самое | 143 |
| SIGUSR1 | `kill -USR1 <pid>` | печать текущего состояния линии, работа продолжается | - |
| SIGUSR2 | `kill -USR2 <pid>` | мягкая остановка: новые заготовки не выпускаются, детали в работе доделываются | 140 (или 0, если план успел выполниться) |

Пример вывода по SIGUSR1:

```
--- Состояние линии, t=40 ---
Выпуск: REDUCER 0/4
Склад: 3, вход ОТК: 0/3, выход ОТК: 0/2
Станки: LATHE-1[SHAFT#10] MILL-1[GEAR#11] MILL-2[HOUSING#9] DRILL-1[GEAR#8] GRIND-1[-]
Роботы: РОБОТ-1[HOUSING#12] РОБОТ-2[GEAR#13]
Комплекты: SHAFT 1/4 GEAR 0/4 HOUSING 1/4
---
```

## 3. Что выводит программа

### В начале - параметры

```
Параметры: роботов 2 (перевозка 2), контролёров 1 (контроль 1), постов 1 (сборка 5)
Накопители: очередь станка 3, выход станка 1, вход ОТК 3, выход ОТК 2, комплект 4
Деталь SHAFT: заготовок 6, брак 10%, переделка с операции 2 до 1 раз, маршрут: LATHE(4) GRIND(3)
...
```

| Событие | Когда |
|---|---|
| `СИСТЕМА` | запуск линии, получен сигнал |
| `СОЗДАНИЕ` | склад выпустил заготовку |
| `ОЧЕРЕДЬ` | деталь поставлена в накопитель или очередь |
| `ПЕРЕВОЗКА` | робот взял или доставил деталь |
| `ОП.НАЧАЛО`, `ОП.КОНЕЦ` | станок начал / закончил операцию |
| `ПРОСТОЙ` | выход станка или ОТК заполнен - участник ждёт места |
| `КОНТРОЛЬ` | контролёр начал проверку / деталь годна |
| `БРАК` | контролёр нашёл брак |
| `ПЕРЕДЕЛКА` | бракованная деталь возвращается на операцию |
| `СПИСАНИЕ` | деталь списана, склад выпустит замену |
| `КОМПЛЕКТ` | деталь поступила в комплект для сборки |
| `СБОРКА`, `ВЫПУСК` | пост начал сборку / выпустил изделие |
| `!ИНВАРИАНТ` | нарушено правило модели (в нормальной работе не появляется) |

### В конце - итоги

```
========== ИТОГИ МОДЕЛИРОВАНИЯ ==========
Завершение: ПЛАН ВЫПОЛНЕН
Причина: все изделия по плану выпущены
Время работы: 93 ед. (1.9 с), потоков участников: 10
Событий: 449, seed: 13
Проверок правил: 134, нарушений правил модели: 0
Изделие REDUCER: выпущено 4 из 4
Средний цикл изделия: 58.2, такт выпуска: 23.2
Деталь SHAFT: создано 4, брак 1, переделок 1, списано 0, в изделиях 4, на линии 0, ср. путь до комплекта 29.5
...
Станок GRIND-1: операций 13, работа 33.2%, приостановлен 9.7%
Контролёр ОТК-1: проверено 18, брак 2, работа 19.3%, ожидание места 0.0%
Робот РОБОТ-1: рейсов 39, работа 83.4%
Пост ПОСТ-1: собрано 4, работа 21.4%
Максимальное заполнение: склад 8, вход ОТК 1/3, выход ОТК 1/2
=========================================
```

«Средний цикл изделия» - сколько в среднем проходит от создания первой детали комплекта до выпуска изделия, «такт выпуска» - как часто выходит новое изделие, «ср. путь до комплекта» - сколько деталь в среднем идёт от склада до сборки. «Работа 33%» - какую долю всего времени участник был занят делом. «Приостановлен» - сколько станок простоял с готовой деталью, потому что её некуда было положить.

Всё, что выводится на экран, плюс параметры, пишется и в журнал (`line.log`).

## 4. Варианты завершения

| Код | Итог | Когда |
|---|---|---|
| 0 | ПЛАН ВЫПОЛНЕН | выпущены все изделия по плану |
| 1 | ошибка | ошибка в файле, неверный ключ, нет файла |
| 2 | ИСХОДНЫЕ ДЕТАЛИ ИСЧЕРПАНЫ | заготовок не хватило (с учётом списаний) |
| 3 | ПРОИЗВОДСТВО НЕВОЗМОЖНО | невыполнимые данные или взаимная блокировка накопителей |
| 4 | ПРЕВЫШЕН ЛИМИТ ВРЕМЕНИ | достигнут лимит `-t` |
| 5 | - | нарушены правила модели (ошибка программы) |
| 130 / 143 | ПРЕРВАНО СИГНАЛОМ | SIGINT / SIGTERM |
| 140 | МЯГКАЯ ОСТАНОВКА | SIGUSR2, детали в работе доделаны |

Узнать код после запуска: `echo $?`.
